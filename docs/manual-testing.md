# 手测场景

覆盖：选题（= 会话）的创建与上下文隔离、对话历史提取、产物登记与产物库、todo 任务面板、界面要素。每条场景给出可直接复制的消息序列和判定标准。

## 前提

- **必须用真实模型**（设置对话框填 API key）。dev 模式的 faux 模型只是回声，测不了召回与提取。
- 判定技巧：用生僻代号（「蓝鲸-42」、ZX-7391、QT-2048），对错无歧义，避免模型"蒙对"常见词。
- 闲聊填充轮**不能出现"代号、预算、密码、蓝鲸"等关键词**，否则测不出真召回。
- 场景 1 失败时先区分链路问题还是模型能力问题：把同样对话粘到该模型的官方网页版里问，官方能答而 Siftory 答不出，才是上下文组装的 bug。
- 每个选题的工作目录是 `workspace/topics/<会话id>/`（dev 模式数据目录默认 `apps/agent/.data/`）；手测后清理该目录。

## 1. 对话历史提取（同一选题内）

从首页发起框创建选题后，在同一选题页内依次发送。

### 1.1 直接召回（基线，9 条消息）

```
① 请记住：我的项目代号是「蓝鲸-42」，预算上限 87 万元。只回复"已记录"。
```

检查点：回复"已记录"。

```
② 今天天气怎么样？
③ 帮我把"知识就是力量"翻译成英语。
④ 写一首关于秋天的四句短诗。
⑤ 345 乘以 27 等于多少？
⑥ 推荐一道十块钱以内能做的家常菜。
```

正常等每轮回答完再发下一条。

```
⑦ 我的项目代号和预算上限分别是多少？
```

✅ 通过：准确答出「蓝鲸-42」和 87 万元。❌ 失败：说不知道、编造别的代号、或只答对一个。

### 1.2 分散信息聚合（4 条消息）

```
① 第一批采购了 3 箱苹果。
② 顺便问一下，纸箱回收一般卖多少钱一斤？
③ 第二批又采购了 5 箱。
④ 一共采购了几箱苹果？
```

② 与采购数量无关，仅作间隔。✅ 通过：答 8 箱（跨两条消息聚合）。❌ 失败：只答 5 箱（只看了最后一条）或答不出。

### 1.3 指代与规则持久（5 条消息）

```
① 我们约定：之后回答都用不超过十个字。
② 现在几点了？
③ 地球上的海洋面积占比大约是多少？
④ 我们之前定的回答规则是什么？
⑤ 这条规则从哪条消息开始生效的？
```

②③ 顺带观察：回答是否 ≤ 10 个字（规则生效中）。✅ 通过：④ 复述出"回答不超过十个字"（复述内容本身超字数不算违反）。⑤ 是加分项：能指出规则来自第一条消息，答不出不影响通过。

### 1.4 超出 UI 窗口的历史（可选，费 token）

聊到消息数超过 200 条后，问第一条消息的内容。

✅ 通过：模型答得出。UI 的 200 条窗口只是投影分页（"加载更早"按钮），模型上下文不受它限制。此场景同时验证"加载更早"按钮能翻出旧消息。

## 2. 选题隔离与导航

选题 = 会话。新选题天然是全新上下文，不存在"清理不干净"的问题；隔离考察的是两个选题互不串扰、配置正确继承。

### 2.1 核心流程：选题 A 设秘密 → 选题 B 验证遗忘（5 步）

首页发起框创建选题 A：

```
① 记住：我的门禁密码是 ZX-7391。
② 我的门禁密码是多少？
```

对照组检查点：② 答出 ZX-7391。答不出说明模型本身召回弱，换强模型再测，不要继续。

**③ 点左上角「‹ 产物库」回首页，从发起框创建选题 B（任意主题，如"推荐三部科幻小说"）。**

```
④ 我的门禁密码是多少？
⑤ 我们之前聊过什么？
```

✅ 通过：④ 明确表示不知道；⑤ 只提到本轮内容。❌ 失败：答出 ZX-7391，或复述出选题 A 的任何内容。

### 2.2 回到选题 A 仍在（接 2.1）

回首页，点选题 A 的卡片（在「进行中」或「已完成」区），进入后：

```
⑥ 我的门禁密码是多少？
```

✅ 通过：答出 ZX-7391——选题 A 的上下文完好保存在自己的会话里。同时检查：选题 A 的聊天记录完整可见。❌ 失败：历史丢失或密码遗忘（会话绑定错了容器）。

### 2.3 配置继承与按选题改模型（4 步）

**① 回首页，设置对话框 → 自定义指令填 `每次回答开头加一个 🤖`，保存。**

**② 从发起框创建新选题 C，发 `你好`。**

检查点：回答以 🤖 开头——新选题继承了 root 模板（首页设置）的指令与模型。

**③ 在选题 C 的输入框左下模型选择里换一个模型，发 `你好`。**

检查点：header chip 的模型名立即变化，回答仍以 🤖 开头（指令不受换模型影响）。

**④ 回首页再创建选题 D，发 `你好`。**

✅ 通过：选题 D 用的是 root 模板的模型（不是选题 C 刚换的那个），回答以 🤖 开头。按选题改的配置不污染默认值模板。❌ 失败：任一检查点不符。

### 2.4 单并发约束

创建一个会长跑的选题（如"写 500 字散文"），流式输出中途回首页。

检查点：发起框**禁用**并提示有选题进行中；进行中的选题卡在「进行中」区显示。

✅ 通过：无法发起新选题，直到该选题完成或在选题页点「停止」。补充：运行中直接回到进行中的选题，可以再发消息（进入排队）。

### 2.5 重启后库与选题仍在（持久性）

完成 2.1 后退出应用并重启。

✅ 通过：首页显示选题 A/B；选题 A 打开后历史完整、密码仍记得。选题与产物索引是持久提交，不是内存状态。❌ 失败：库空了或选题历史丢失。

## 3. todo 任务面板与工具卡片

两个观察面：输入框上方的**任务面板**（模型调 todo 工具后出现，随提交实时刷新，纯展示不可点击）；聊天流里的**工具卡片**（工具名 + 状态 + 可展开输出，失败红色左边线且默认展开；连续 ≥3 个工具调用折叠成一组，点击展开）。这些场景同时验证三方一致：面板、模型口中的列表、选题目录里的真实文件。

注意措辞：不要说「在 workspace 目录新建」——模型的工作目录本身就是选题目录，那样说会让它再嵌套一层。

### 3.1 建列表（含闲聊负面检查，2 条消息）

新选题里先验证负面情形：

```
① 今天天气怎么样？
```

检查点：面板**不出现**（单个琐碎任务不该建列表）。

```
② 帮我做三件事，先逐个建成任务列表，暂时不要执行：
1) 新建 hello.txt，内容写「蓝鲸-42」；
2) 新建 notes.md，写三行任意笔记；
3) 把 hello.txt 复制一份为 hello-copy.txt。
```

✅ 通过：面板出现 3 条任务，计数「任务 0/3」；聊天流里能看到 todo 工具卡。❌ 失败：面板不出现、条目数不对、主题与消息不符。

### 3.2 执行并核对真实文件（接 3.1，1 条消息）

```
③ 按顺序执行这三个任务。
```

观察面板（不要刷新页面）：同一时刻只有一条**进行中**并高亮；完成的任务逐条划线；聊天流依次出现 write、bash 等工具卡；最终计数「任务 3/3」。

**文件系统验证**：打开该选题的目录（`workspace/topics/<会话id>/`）——`hello.txt` 内容为「蓝鲸-42」、`hello-copy.txt` 内容相同、`notes.md` 有三行。

✅ 通过：面板状态、工具卡、磁盘文件三者一致。❌ 失败定位：聊天里没有工具卡 → 模型没用工具（换强模型再测）；有工具卡但文件不对 → 工具链路 bug；文件对但面板不动 → 面板投影 bug。注：模型动作太快看不清中间态时，补发「每个任务之间停顿一下，逐步播报进度」再观察。

### 3.3 依赖、删除、清空（接 3.2，4 条消息）

```
④ 加一个任务：把 hello-copy.txt 里的代号改成 QT-2048。它被「复制 hello.txt」那个任务阻塞。
```

检查点：新条目带 ⛓ #N 标记，N 是「复制 hello.txt」的任务编号。

```
⑤ 执行刚才加的这个任务。
```

文件验证：`hello-copy.txt` 内容变为 QT-2048，`hello.txt` 不变；聊天出现 edit 或 write 工具卡。

```
⑥ 把「新建 notes.md」这个任务删掉。
⑦ 把任务列表清空。
```

✅ 通过：⑤ 后文件内容正确且面板该条划线；⑥ 后「新建 notes.md」从面板消失（墓碑删除，默认不展示）；⑦ 后面板整体消失。❌ 失败：依赖标记缺失或指错编号、删错条目、改错了文件、清空后残留空框。

### 3.4 重启恢复与按选题保留（持久性）

接 3.2 状态（列表里有勾选也有未勾选）。完全退出应用再打开，从首页点进该选题。

✅ 通过：面板与退出前完全一致（含勾选与划线状态）；聊天流里的工具卡也还在。再回首页进入一个**别的**选题：那边不出现本选题的任务列表——任务列表按选题（会话）各自保存。❌ 失败：面板空了、状态回退、或串到别的选题。

## 4. 产物登记与产物库

产物协议：模型把最终交付物写进选题目录后，调 `register_artifact` 登记，产物才会出现在首页产物库。

### 4.1 登记 → 卡片出现（1 个选题，2 条消息）

新选题：

```
① 写一份关于固态电池进展的简短研究报告（三四段即可），存成 report.md，然后把报告登记为产物。
② 再写一段 100 字左右的摘要，存成 summary.md，也登记为产物。
```

✅ 通过：聊天流出现 `register_artifact` 工具卡且状态完成；选题目录下两个文件都被移入 `artifacts/`。回首页：该选题卡出现在「已完成」区——主视觉是**后登记的摘要**（阶段相同则取最后登记），其余产物以小行列出；主视觉含摘要开头几行摘录。❌ 失败：工具卡报错、文件没移动、首页卡片不出现或主视觉不对。

### 4.2 阶段决定主视觉（接 4.1，1 条消息）

```
③ 把报告正文压缩成一条 60 秒口播文案，存成 script.md，登记时 stage 填 narrate。
```

✅ 通过：回首页后卡片主视觉换成口播文案（narrate 在管道顺序上晚于 synthesize），报告退到小行。❌ 失败：主视觉没变。

### 4.3 打开选题与产物文件

点首页卡片进入选题。

✅ 通过：聊天记录完整；`artifacts/report.md` 等文件在磁盘上可读；`artifacts/` 之外选题目录里没有遗留这两个文件（登记是移动不是复制）。❌ 失败：聊天丢失或文件对不上。

### 4.4 登记守卫（可选）

```
④ 把 /etc/hosts 登记为产物。
```

✅ 通过：工具卡失败并提示路径必须在选题目录内。❌ 失败：登记成功（路径守卫失效）。

## 5. 界面要素（smoke）

- **空库引导**：全新数据目录启动，首页显示「从信息到故事。」与三个示例选题；点示例填入发起框（不直接发出）；发送后进入新选题页。
- **设置对话框**：header「设置」打开居中对话框，Esc 或点遮罩关闭；对话区不被替换；保存后立即生效。
- **状态 chip**：header 显示连接点（绿=已连接，红=断开）+ 模型 id；选题页排队时追加「排队 N」；tooltip 有完整 provider/model。
- **工具卡片**：点击展开/收起输出；失败的红色左边线且默认展开；连续 ≥3 个工具调用折叠为「N 个工具调用」，点击展开逐个看。
- **暗色主题**：设置里切深色，以上各面（首页卡片、工具卡、对话框）无对比度/边线异常。

## 未覆盖

- WS 断线重连中途切换选题的竞态：守卫代码已加（加载历史期间切换上下文会丢弃旧分页），但手工难以稳定复现。
- 纯闲聊选题（无产物）完成后不进首页「已完成」区（设计如此），数据留在 SQLite，UI 没有找回入口。
- 无删除入口（设计如此）：选题与产物只增不减；清理靠手动删 `workspace/topics/<目录>`（索引行残留，重启后该选题卡片会因找不到文件而显示异常——已知欠账）。
- todo 面板是纯展示，不能手动勾选改状态——写入的唯一入口是模型的 todo 工具。
- 工具卡只展示工具名、状态与输出（超长截断 800 字），不渲染调用参数与耗时；需要参数级排查时看 SQLite 里的原始条目。
- 产物文件的页内预览（播放器/全文阅读）未实现，属第 3 期；当前验证产物靠文件系统直读。
