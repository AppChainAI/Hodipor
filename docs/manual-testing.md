# 手测场景：上下文提取与新会话隔离

覆盖两条链路：模型对当前会话历史的提取能力，以及「新会话」（reset）后的上下文隔离与界面状态。每条场景给出完整可直接复制的消息序列和判定标准。

## 前提

- **必须用真实模型**（设置页填 API key）。dev 模式的 faux 模型只是回声，测不了召回与提取。
- 判定技巧：用生僻代号（「蓝鲸-42」、ZX-7391、QT-2048），对错无歧义，避免模型"蒙对"常见词。
- 闲聊填充轮**不能出现"代号、预算、密码、蓝鲸"等关键词**，否则测不出真召回。
- 场景 1 失败时先区分链路问题还是模型能力问题：把同样对话粘到该模型的官方网页版里问，官方能答而 Siftory 答不出，才是上下文组装的 bug。

## 1. 对话历史提取（同一上下文内）

### 1.1 直接召回（基线，9 条消息）

```
① 请记住：我的项目代号是「蓝鲸-42」，预算上限 87 万元。只回复"已记录"。
```

检查点：回复"已记录"。

```
② 今天天气怎么样？
③ 帮我把"知识就是力量"翻译成英语。
④ 写一首关于秋天的四句短诗。
⑤ 345 乘以 27 等于多少？
⑥ 推荐一道十块钱以内能做的家常菜。
```

正常等每轮回答完再发下一条。

```
⑦ 我的项目代号和预算上限分别是多少？
```

✅ 通过：准确答出「蓝鲸-42」和 87 万元。❌ 失败：说不知道、编造别的代号、或只答对一个。

### 1.2 分散信息聚合（4 条消息）

```
① 第一批采购了 3 箱苹果。
② 顺便问一下，纸箱回收一般卖多少钱一斤？
③ 第二批又采购了 5 箱。
④ 一共采购了几箱苹果？
```

② 与采购数量无关，仅作间隔。✅ 通过：答 8 箱（跨两条消息聚合）。❌ 失败：只答 5 箱（只看了最后一条）或答不出。

### 1.3 指代与规则持久（5 条消息）

```
① 我们约定：之后回答都用不超过十个字。
② 现在几点了？
③ 地球上的海洋面积占比大约是多少？
④ 我们之前定的回答规则是什么？
⑤ 这条规则从哪条消息开始生效的？
```

②③ 顺带观察：回答是否 ≤ 10 个字（规则生效中）。✅ 通过：④ 复述出"回答不超过十个字"（复述内容本身超字数不算违反）。⑤ 是加分项：能指出规则来自第一条消息，答不出不影响通过。

### 1.4 超出 UI 窗口的历史（可选，费 token）

聊到消息数超过 200 条后，问第一条消息的内容。

✅ 通过：模型答得出。UI 的 200 条窗口只是投影分页（"加载更早"按钮），模型上下文不受它限制。此场景同时验证"加载更早"按钮能翻出旧消息。

## 2. 新会话隔离（reset）

### 2.1 核心流程：设秘密 → 验证 → 新会话 → 验证遗忘（5 步）

```
① 记住：我的门禁密码是 ZX-7391。
② 我的门禁密码是多少？
```

对照组检查点：② 答出 ZX-7391。答不出说明模型本身召回弱，换强模型再测，不要继续。

**③ 点界面右上角「新会话」。**

界面检查点：消息列表立即清空；「加载更早的消息」按钮消失；header 模型名不变。

```
④ 我的门禁密码是多少？
⑤ 我们刚才聊过什么？
```

✅ 通过：④ 明确表示不知道/没有相关信息；⑤ 回答类似"这是第一条消息"或只提到 ④。❌ 失败：答出 ZX-7391，或复述出 reset 前的任何内容。

### 2.2 新上下文正常工作且不串扰（接 2.1 之后，2 条消息）

```
⑤ 记住：新密码是 QT-2048。
⑥ 我的密码是多少？之前的旧密码呢？
```

✅ 通过：只答 QT-2048，对旧密码表示没有记录——新上下文功能正常且无污染。❌ 失败：答出 ZX-7391，或连 QT-2048 都不知道（新上下文没正常建立）。

### 2.3 配置不随 reset 丢失（4 步）

**① 设置页 → 自定义指令填 `每次回答开头加一个 🤖`，保存。**

```
② 你好。
```

检查点：回答以 🤖 开头（指令生效）。

**③ 点「新会话」。**

```
④ 你好。
```

✅ 通过：回答仍以 🤖 开头。reset 只清上下文，不动会话的模型与指令配置。❌ 失败：emoji 消失。

### 2.4 忙时新会话

发一个长回答任务（如"写 500 字散文"），流式输出中途点「新会话」。

✅ 通过：当前任务在边界结束，界面清空，不会再把旧回答刷出来。注意：回答太快就赶不上中途点击，需要一个足够长的生成任务。

### 2.5 重启后仍是新上下文（持久性）

完成 2.1 后退出应用并重启。

✅ 通过：界面仍是空的新会话，问密码依然不知道。reset 是持久提交，不是内存状态。

## 3. todo 任务列表与工具调用（面板 + 工具行）

两个观察面：输入框上方的**任务面板**（模型调 todo 工具后出现，随每次提交实时刷新，计数「已完成/总数」，无可见任务时不占位；状态用勾选框表达——待办未勾、进行中半选、完成勾选加划线，面板纯展示不可点击）；聊天流里的**工具行**（⚙ 工具名 + 结果摘要，红色左边线表示失败）。这些场景同时验证三方一致：面板、模型口中的列表、文件系统里的真实结果。

文件工具的工作目录是**数据目录下的 `workspace/`**（dev 模式默认 `apps/agent/.data/workspace/`）；手测前清空该目录，测后清理。

### 3.1 建列表（含闲聊负面检查，2 条消息）

新会话后先验证负面情形：

```
① 今天天气怎么样？
```

检查点：面板**不出现**（单个琐碎任务不该建列表）。

```
② 帮我做三件事，先逐个建成任务列表，暂时不要执行：
1) 新建 hello.txt，内容写「蓝鲸-42」；
2) 新建 notes.md，写三行任意笔记；
3) 把 hello.txt 复制一份为 hello-copy.txt。
```

注意措辞：不要写「在 workspace 目录新建」——模型的工作目录本身就是 workspace/，那样说会让它再嵌套一层 workspace/workspace/。

✅ 通过：面板出现 3 条任务，勾选框均未勾，计数「任务 0/3」；聊天流里能看到 ⚙ todo 工具行。❌ 失败：面板不出现、条目数不对、主题与消息不符。

### 3.2 执行并核对真实文件（接 3.1，1 条消息）

```
③ 按顺序执行这三个任务。
```

观察面板（不要刷新页面）：同一时刻只有一条**半选**（进行中）并显示进行时标签；完成的任务逐条**勾选并划线**；聊天流依次出现 ⚙ write、⚙ bash 等工具行；最终计数「任务 3/3」。

**文件系统验证**：打开 workspace 目录——`hello.txt` 内容为「蓝鲸-42」、`hello-copy.txt` 内容相同、`notes.md` 有三行。

✅ 通过：面板状态、工具行、磁盘文件三者一致。❌ 失败定位：聊天里没有工具行 → 模型没用工具（换强模型再测）；有工具行但文件不对 → 工具链路 bug；文件对但面板不动 → 面板投影 bug。注：模型动作太快看不清中间态时，补发「每个任务之间停顿一下，逐步播报进度」再观察。

### 3.3 依赖、删除、清空（接 3.2，4 条消息）

```
④ 加一个任务：把 hello-copy.txt 里的代号改成 QT-2048。它被「复制 hello.txt」那个任务阻塞。
```

检查点：新条目带 ⛓ #N 标记，N 是「复制 hello.txt」的任务编号。

```
⑤ 执行刚才加的这个任务。
```

文件验证：`hello-copy.txt` 内容变为 QT-2048，`hello.txt` 不变；聊天出现 ⚙ edit 或 ⚙ write 工具行。

```
⑥ 把「新建 notes.md」这个任务删掉。
⑦ 把任务列表清空。
```

✅ 通过：⑤ 后文件内容正确且面板该条划线；⑥ 后「新建 notes.md」从面板消失（墓碑删除，默认不展示）；⑦ 后面板整体消失。❌ 失败：依赖标记缺失或指错编号、删错条目、改错了文件、清空后残留空框。

### 3.4 重启恢复（持久性，接 3.2 状态重建后）

若列表已清空，先重建：重发 3.1② 并执行其中一两个任务，让列表里同时有「已勾选」和「未勾选」。然后完全退出应用再打开。

✅ 通过：面板与退出前完全一致（含勾选与划线状态）；聊天流里的工具行也还在（历史消息含工具结果）。❌ 失败：面板空了、状态回退、或工具行丢失。

### 3.5 新会话后列表清空（宿主策略）

接 3.4 状态，点「新会话」。

检查点：面板**立即消失**（任务列表随新会话清空）。

```
① 我现在的任务列表里有什么？
```

✅ 通过：面板不出现；模型答没有任何任务。背景：durable 引擎的 reset 只开新上下文、不回退会话文档，「新会话清空任务」是宿主在 reset 端点上主动清空 app.todos 的产品策略。❌ 失败：面板残留旧任务，或模型复述出旧任务。

## 未覆盖

- WS 断线重连中途遇 reset 的竞态：守卫代码已加（加载历史期间切换上下文会丢弃旧分页），但手工难以稳定复现。
- reset 前的旧数据仍保留在 SQLite 中（设计如此），界面没有找回入口；需要的话属于多会话功能的范畴。
- todo 面板是纯展示，不能手动勾选改状态——写入的唯一入口是模型的 todo 工具，手动管理属于新功能。
- reset 不回退 app.todos 文档（已实测确认）；「新会话清空任务」由宿主在 /api/reset 端点主动清空，属产品策略而非引擎行为，3.5 覆盖该路径。
- 工具行只展示工具名与结果摘要（超长截断 800 字），不渲染调用参数；需要参数级排查时看 SQLite 里的原始条目。
